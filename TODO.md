Goal:
One command syncs the notes you already track: newest version wins everywhere,
even when edited in both places. Sync only by Anki noteId. We track Anki notes
(one note -> N cards generated by Anki), never individual cards.

Three commands with distinct jobs (see "Agreed command model" below): the
import wizard brings Anki notes into the vault, the export wizard creates new
notes in Anki, and Sync is the only command that updates notes on either side.
Fields, tags and deck map both ways; notetype changes and card-level
properties are out of scope (ENT-07).

Card side is informational only: the `cards[]` array from `notesInfo` is never
addressed (there is no "update card #2" API). Per-card operations (e.g. suspend
one side of a reversed pair) are out of MVP scope; a card-level layer may be
added later alongside notes, not instead of them.

Note states (per note; state = existence x id x sync record x dirtiness):
- ankiOnly.neverImported: Anki-only, never imported, no sync record -> import (create file). Owned by the import wizard, not by Sync (Sync only touches tracked notes; untracked Anki notes are counted as "needs import").
- ankiOnly.fileDeleted: Anki-only, has sync record, file deleted in vault -> tombstone rule (SYNC-01/SYNC-02): resurrect iff Anki mod is newer than deletion.
- synced.clean: both sides, clean (mod and hash match records) -> do nothing.
- synced.ankiNewer: only Anki newer -> push Anki -> vault.
- synced.vaultNewer: only vault newer -> push vault -> Anki.
- synced.diverged: both dirty -> compare Anki mod vs file mtime, newer wins.
- linked.unenrolled: linked by ID but no sync record -> enroll (store mod + hash), then handle as synced.*.
- vaultOnly.unexported: vault-only, no ID, never uploaded -> export (create in Anki, write back ID + sync records).
- vaultOnly.unenrolled: vault-only, has ID, no sync record (fresh data.json, manual ID) -> match by hash, enroll, then handle as synced.*.
- vaultOnly.ankiDeleted: vault-only with ID + sync record, note gone in Anki -> delete file, purge records + tombstone (Anki deletion always wins).
- orphaned: nowhere, stale sync records -> purge records.
- Identity is per block, not per file: a deleted file and a deleted block inside a living file are both missing; never recreate either.
- Origin matters exactly once: an Obsidian-born note without ID must go through export (vaultOnly.unexported) first; afterwards origin is irrelevant.

Agreed sync mechanics:
- SYNC-01: tombstones on vault delete event (reverse path -> noteId index, persisted noteId -> deletedAt); cleaned on sync when the note is also gone in Anki.
- SYNC-02: no tombstone (deleted outside Obsidian): Anki newer than recorded mod -> resurrect, otherwise respect deletion (purge, no recreate).
- SYNC-03: Anki deletion wins unconditionally (AnkiConnect has no deletion timestamps); delete file even with vault edits.
- SYNC-04: tie-break Obsidian wins by default; settings syncTieWinner ("obsidian" | "anki") + syncTieThresholdSec = 60; ties are reported.
- SYNC-05: missing files/blocks are skipped, counted, never recreated.
- SYNC-06: diverged notes are resolved by newest-wins (vault push vs anki pull), counted separately as pushed / refreshed.
- SYNC-07: mtime (TFile.stat.mtime, ms) is the vault-side clock vs Anki mod (unix seconds); own writes are safe because verdicts go through hashes first.
- SYNC-08: force is explicit and per note, offered on every row of both wizards, off by default, and is the mirror of SYNC-08 on the other side: "Anki wins" in the import wizard (FORCE_PULL from synced.vaultNewer and synced.diverged, RESURRECT from ankiOnly.fileDeleted) and "Obsidian wins" in the export wizard (FORCE_PUSH from synced.ankiNewer and synced.diverged, EXPORT from vaultOnly.ankiDeleted). Where the command already takes the preferred side, marking the row changes nothing; the report names the forced count, which counts only the forces that overrode a guard.
- SYNC-09: deck is mapped in both directions. Vault path is the source of truth for the target deck (deckForPath); a path change issues changeDeck for the cards currently in the ledger deck only; an Anki-side deck change (read via cardsInfo, notesInfo has no deck) moves the file to deckFolder. A note with cards in more than one deck is reported as ambiguous, never collapsed.
- SYNC-10: ignored directories are plugin-wide: no scan, no index, no ID filling, no purge, no import target. A ledger record whose file sits in an ignored folder is reported as out of scope and never purged, so the setting can never become a data-loss switch.

Agreed command model (the reason this plugin exists; one line per command):
- `Import deck from Anki` (wizard): Anki to vault for a chosen deck. Pull only: it never writes to Anki, never purges, never resolves deletions, and never overwrites a note whose vault side is newer unless the user forces that single note. It discovers models, maps fields, creates missing packs, shows the direction of every change, and writes the result report.
- `Export deck from Obsidian` (wizard): the exact mirror of the import wizard, vault to Anki for a chosen deck. Scope: one Anki deck, showing how many vault notes map to it and how many already exist in Anki. It creates missing notes, pushes what changed in Obsidian, and never guesses: a note edited in both places, a note newer in Anki, and a note deleted in Anki wait for the user, named in the report as "use Sync" or "use Obsidian wins" - the per-row force ("Obsidian wins", the mirror of "Anki wins", off by default, plus a bulk button) takes the Obsidian version regardless of state, including recreating a note deleted in Anki.
- `Sync`: the whole-ledger sweep over everything already tracked - bidirectional, newest version wins, no action when the ledger is empty. It is the command that resolves edits made in Anki in bulk, plus deletions, deck moves and tombstones, without asking per note. Also available for a single note (active file).
- Rare actions stay in the command palette (including `Purge ledger`); the single ribbon icon is Sync.
- Each command resolves its own states through its own resolver over the one transition table (`importActFor`, `exportActFor`, `syncActFor`), so the three commands are mirrors of each other rather than three policies: a wizard never resolves a conflict by clocks, only the user (force) or Sync does.
